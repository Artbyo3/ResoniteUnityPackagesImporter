## Findings

1. **Import completion does not mean correct size.** `k` completed in approximately 1.2 seconds. ResoLoop found one enabled SkinnedMeshRenderer, an assigned mesh, one XiexeToonMaterial, a main texture reference, and nine non-null bone references. Two camera captures show extremely large wings. The renderer Slot has scale approximately `(100,100,100)`; the source prefab also contains 100-scale transforms, while its local mesh bounds are small. The FBX metadata has `globalScale: 1` and `useFileScale: 1`. This points toward inconsistent FBX unit/bind-pose handling, but the exact conversion error is not yet isolated. Do not apply a blanket 0.01 scale correction without comparing mesh and bone spaces.
2. **Shared humanoid metadata races.** At 21:43:23 the log reports `Collection was modified; enumeration operation may not execute` in `MetaDataFile.GenerateComponents`. `SettupHumanoid` rescans `task.metafile`, clearing and repopulating dictionaries. Multiple prefabs use the same template task concurrently. Replacing this with per-call metadata also prevents one avatar instance's bone Slots from becoming another instance's mappings.
3. **Missing renderer finalization crashes.** MANUKA attempts logged `NullReferenceException` in `UnityPrefabImportTask.StartImport`. That method dereferenced `createdMeshRenderer` in both its enable loop and its IK-selection loop without checking whether renderer reconstruction succeeded. Guards prevent this secondary crash, but do not reconstruct a missing mesh; missing renderers now produce a contextual warning. The original exception did not include source line numbers, so a restart/retest is still required to confirm all causes are addressed.
4. **Large imports need better resource and log management.** FILE imports overlapped many prefab tasks and the log records FPS falling as low as 17–19. This is observational evidence, not a controlled performance benchmark. Progress and diagnostics should summarize per asset rather than dump every bone/object; importing selected prefabs would avoid creating all variants at once.
5. **Cache publication depends on the filesystem location.** The `k` audit failed with an access-denied directory move under the long OneDrive project path, including outside the sandbox. The same archive extracted successfully to a short local temporary path and in Resonite's cache. The precise filesystem/path cause remains unresolved.

## Fixes built after testing

- Humanoid setup now creates instance-local metadata and returns to the world thread before inspecting/creating rig components.
- Skip already initialized VRIK roots and avoid division by zero/non-finite height during automatic normalization.
- Skip missing renderers with a warning during prefab finalization instead of dereferencing null.
- Add a reusable real-package extraction audit command:
